# Задание: Скрипт-оркестратор для выполнения задач через локальные LLM (Ollama / LM Studio)

## Общая идея

Нужен Python-скрипт, который:
1. Читает файл `task.md` с описанием общей задачи.
2. Разбивает эту задачу на подзадачи с помощью LLM и сохраняет каждую подзадачу как отдельный `.md`-файл в папке `tasks/`.
3. Спрашивает пользователя, какой backend использовать — Ollama или LM Studio.
4. Выполняет подзадачи по очереди, отправляя их выбранной модели, отслеживает прогресс и выводит процент выполнения.

## Структура проекта после запуска

```
project/
├── script.py           # основной скрипт
├── task.md             # исходное описание задачи (пишет пользователь)
├── tasks/               # создаётся скриптом
│   ├── 01_step_name.md
│   ├── 02_step_name.md
│   └── ...
├── output/              # создаётся скриптом — результаты выполнения каждой подзадачи
│   ├── 01_step_name.md
│   └── ...
├── progress.json        # создаётся скриптом — статус выполнения каждой подзадачи
└── config.json          # создаётся скриптом при первом запуске (сохранённый выбор backend/модели)
```

## Порядок работы скрипта

### Шаг 1. Запуск и проверка окружения
- Проверить, что `task.md` существует в текущей папке. Если нет — вывести понятную ошибку и завершиться.
- Создать папки `tasks/` и `output/`, если их нет.

### Шаг 2. Выбор backend
При первом запуске (или если нет `config.json`) спросить пользователя в интерактивном режиме:

```
Выберите backend для выполнения задач:
1) Ollama (http://localhost:11434)
2) LM Studio (http://localhost:1234)
Введите номер:
```

После выбора:
- Запросить список доступных моделей у выбранного backend (через API) и дать пользователю выбрать модель из списка.
- Сохранить выбор (backend, base_url, имя модели) в `config.json`, чтобы при следующем запуске не спрашивать заново (но дать флаг `--reconfigure` для повторной настройки).

**API для получения списка моделей:**
- Ollama: `GET http://localhost:11434/api/tags`
- LM Studio: `GET http://localhost:1234/v1/models` (OpenAI-совместимый формат)

### Шаг 3. Разбиение task.md на подзадачи
- Прочитать содержимое `task.md`.
- Отправить выбранной модели промпт-планировщик (см. раздел «Промпт для разбиения задачи» ниже).
- Ожидать от модели строго JSON-ответ со списком шагов.
- Для каждого шага создать файл `tasks/NN_slug.md`, где:
  - `NN` — порядковый номер с ведущим нулём (01, 02, ...)
  - `slug` — короткое имя шага латиницей, без пробелов (например, `hero_section`)
  - Содержимое файла — заголовок, описание и ожидаемый результат шага (см. шаблон ниже).
- Вывести в консоль список созданных подзадач.

**Если модель вернула невалидный JSON** — сделать до 2 повторных попыток с уточняющим промптом ("верни только JSON, без markdown-разметки и пояснений"). Если не получилось — сохранить сырой ответ в `tasks/00_raw_plan_failed.md` и сообщить пользователю, что нужно разбить задачу вручную.

### Шаг 4. Выполнение подзадач по очереди
Для каждого файла в `tasks/` (в порядке номеров):
1. Прочитать содержимое подзадачи.
2. Собрать краткий контекст: что уже сделано в предыдущих шагах (краткое summary, НЕ полный текст всех предыдущих ответов — иначе промпт разрастётся).
3. Отправить модели промпт вида:
   ```
   Контекст (что уже сделано): {краткое summary}
   
   Текущая подзадача:
   {содержимое tasks/NN_slug.md}
   
   Выполни только эту подзадачу. Не повторяй предыдущие шаги.
   ```
4. Сохранить полный ответ модели в `output/NN_slug.md`.
5. Обновить `progress.json`: пометить шаг как `done`, записать время выполнения.
6. Обновить краткое summary (можно попросить модель одним предложением резюмировать, что было сделано на этом шаге — отдельным лёгким запросом, либо просто взять первую строку/заголовок ответа).
7. Вывести в консоль прогресс:
   ```
   [======>          ] 3/8 (37%) — выполняется: hero_section
   ```

### Шаг 5. Завершение
- После выполнения всех подзадач вывести итоговую сводку: сколько шагов выполнено, сколько заняло времени, какие файлы созданы.
- Если какой-то шаг завершился ошибкой (нет ответа от API, таймаут) — не прерывать весь процесс, пометить шаг как `failed` в `progress.json`, продолжить со следующего, и в конце вывести список проваленных шагов.

## Промпт для разбиения задачи (использовать как есть)

```
Ты — технический планировщик задач для разработки.

Прочитай задачу ниже и разбей её на 4-8 небольших, последовательных
и самодостаточных подзадач для реализации.

Правила:
- Каждая подзадача должна быть максимально узкой (одна секция, один файл,
  одна функциональность за раз)
- Подзадачи должны идти в порядке выполнения (сначала скелет/структура,
  потом контент, потом стили, потом интерактив, потом финальная проверка)
- Не пиши код, только план
- Не добавляй пояснений вне JSON

Верни ТОЛЬКО валидный JSON строго в этом формате, без markdown-разметки,
без ```json оберток, без каких-либо комментариев:
{
  "steps": [
    {
      "id": 1,
      "title": "короткое название шага",
      "slug": "short_slug_latin",
      "description": "что именно нужно сделать, 2-4 предложения",
      "output_file": "имя файла, который должен получиться или измениться"
    }
  ]
}

Задача:
---
{TASK_MD_CONTENT}
---
```

## Шаблон файла подзадачи (tasks/NN_slug.md)

```markdown
# Шаг {id}: {title}

## Описание
{description}

## Ожидаемый результат
Файл: {output_file}
```

## Технические требования к скрипту

- Язык: Python 3.14+
- Зависимости: только `requests` (без тяжёлых фреймворков типа langchain)
- HTTP-запросы к API с таймаутом (например, 300 секунд на генерацию, т.к. локальные модели могут быть медленными) и обработкой ошибок соединения (backend не запущен — понятное сообщение "Не удалось подключиться к {backend} по адресу {url}. Убедитесь, что сервер запущен.")
- Формат вызова генерации:
  - **Ollama**: `POST http://localhost:11434/api/generate` с телом `{"model": "...", "prompt": "...", "stream": false, "format": "json"}` (параметр `format: json` использовать только для шага планирования, где нужен строгий JSON)
  - **LM Studio**: `POST http://localhost:1234/v1/chat/completions` (OpenAI-совместимый формат) с телом `{"model": "...", "messages": [{"role": "user", "content": "..."}], "stream": false}`
- `progress.json` — простой формат:
  ```json
  {
    "steps": [
      {"id": 1, "slug": "hero_section", "status": "done", "duration_sec": 45.2},
      {"id": 2, "slug": "styles", "status": "pending"}
    ]
  }
  ```
- CLI-флаги:
  - `--reconfigure` — заново спросить backend/модель
  - `--resume` — продолжить с последнего невыполненного шага (по `progress.json`), не начинать заново
  - `--dry-run` — только сгенерировать план подзадач, не выполнять их

## Что НЕ нужно делать
- Не нужно веб-интерфейса, только консоль (CLI)
- Не нужно поддержки нескольких моделей одновременно — только одна выбранная модель на всё выполнение
- Не нужно передавать всю историю переписки в каждый запрос — только текущую подзадачу + краткое summary

Создать файл `README.md` в корне проекта, **на английском языке**, со следующими разделами:

### start.bat
Создать файл `start.bat` (Windows batch-файл) в корне проекта рядом с `task.md`, который:
- Проверяет, что Python установлен и доступен в PATH (иначе выводит понятное сообщение с просьбой установить Python 3.14+ и не закрывает окно сразу — `pause` в конце при ошибке)
- Проверяет наличие установленных зависимостей (`requests`) и, если отсутствуют, устанавливает их через `pip install -r requirements.txt`
- Запускает `python script.py` с передачей всех аргументов, переданных в сам `.bat` (`%*`)
- Не закрывает окно консоли автоматически после завершения работы скрипта, чтобы пользователь успел увидеть итоговую сводку и любые ошибки (`pause` в конце)

Пример логики (для ориентира, не копировать дословно):
```bat
@echo off
where python >nul 2>nul
if %errorlevel% neq 0 (
    echo Python not found. Please install Python 3.14+ and add it to PATH.
    pause
    exit /b 1
)
pip show requests >nul 2>nul
if %errorlevel% neq 0 (
    echo Installing dependencies...
    pip install -r requirements.txt
)
python script.py %*
pause
```
